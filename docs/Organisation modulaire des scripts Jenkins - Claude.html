Deux problèmes distincts, à ne pas confondre.

1. Le message d'erreur (bad permissions) est un vrai souci de permissions, facile à corriger :

bash
chmod 400 ./aws_ec2_install/app-ec2-ssh-key.pem

SSH refuse par sécurité toute clé privée lisible par d'autres que le propriétaire (0664 = trop permissif). Le script aws_create_SSH_key ne fait chmod 400 que lors de la création d'une clé neuve (if [ ! -f "$key_name.pem" ]) — si le fichier existait déjà (copié, ou créé avant ce garde-fou), il ne repasse jamais dessus.

2. Mais regarde bien le nom de fichier dans l'erreur : ./aws_ec2_install/app-ec2-key.pem — sans -ssh- ! Ce n'est pas le nom qu'on utilise actuellement (app-ec2-ssh-key.pem). C'est très probablement le vieux fichier orphelin qu'on avait repéré dans ton tree il y a plusieurs échanges — celui que je t'avais suggéré de supprimer, mais visiblement toujours présent, et ton test_deployments.sh local n'a pas encore reçu le renommage qu'on avait fait de notre côté.

Vérifie ton fichier local :

bash
grep -n "app-ec2.*key" test_deployments.sh

Si ça affiche app-ec2-key.pem (sans -ssh-), c'est confirmé — ton fichier est une version antérieure. Remplace-le par la version à jour ci-dessous, ou corrige juste cette ligne :
